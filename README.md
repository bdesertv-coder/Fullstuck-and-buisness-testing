## Задание 3 — REST API регистрации пользователя

### 3.1 — Описание API

Полное описание в [`Задание 3.docx`](./Задание%203.docx)  
OpenAPI спецификация в [`Задание3.yaml`](./Задание3.yaml)

#### Метод

```
POST /api/v1/users/register
Content-Type: application/json
```

#### Пример запроса

```json
{
  "firstName": "Ivan",
  "lastName": "Ivanov",
  "username": "ivan",
  "password": "P@ssw0rd!",
  "recaptchaToken": "03AGdBq25SxXT..."
}
```

#### Пример успешного ответа `201`

```json
{
  "userId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "username": "ivan",
  "message": "User Register Successfully"
}
```

#### Коды ошибок

| Код | Сторона | code | Описание |
|-----|---------|------|----------|
| 400 | Клиент | `VALIDATION_ERROR` | Пустое поле, недопустимые символы, превышена длина |
| 400 | Клиент | `INVALID_PASSWORD` | Пароль не соответствует правилам сложности |
| 400 | Клиент | `RECAPTCHA_FAILED` | Токен reCAPTCHA не передан, невалиден или просрочен |
| 403 | Клиент | `REGISTRATION_DISABLED` | Регистрация отключена или IP заблокирован |
| 409 | Клиент | `USER_EXISTS` | Username уже занят |
| 415 | Клиент | `UNSUPPORTED_MEDIA_TYPE` | Content-Type не application/json |
| 429 | Клиент | `RATE_LIMIT_EXCEEDED` | Превышен лимит попыток |
| 500 | Сервер | `INTERNAL_ERROR` | Непредвиденная ошибка приложения |
| 502 | Инфраструктура | — | Reverse proxy не получил ответ (отдаёт nginx) |
| 503 | Сервер | `SERVER_UNAVAILABLE` | Сервис временно недоступен |

#### Пример ответа с ошибкой `400`

```json
{
  "code": "INVALID_PASSWORD",
  "message": "В пароле должны содержатся заглавные и строчные латинские буквы (A-Z), цифры (1-9) и спецсимволы (!, _, *, #)",
  "details": {
    "field": "password"
  }
}
```

#### Пример ответа с ошибкой `500`

```json
{
  "code": "INTERNAL_ERROR",
  "message": "Непредвиденная ошибка, попробуйте позже",
  "details": {
    "reason": "internal_server_fault",
    "suggested_action": "retry_with_backoff"
  }
}
```

### 3.2 — Алгоритм создания пользователя на бэкенде

Интерфейс регистрации из ТЗ:

![Интерфейс регистрации](./%D0%A2%D0%B5%D1%81%D1%82_2.drawio%20(1).png)

Блок-схема алгоритма обработки запроса на бэкенде:

![Блок-схема алгоритма регистрации](./%D0%91%D0%BB%D0%BE%D0%BA%20%D1%81%D1%85%D0%B5%D0%BC%D0%B0%20%D0%BA%20%D0%B7%D0%B0%D0%B4%D0%B0%D0%BD%D0%B8%D1%8E%203.2.png)

**Пошаговый алгоритм:**

1. Получение запроса → парсинг тела (JSON)
2. Проверка Content-Type — ожидается `application/json`, иначе `415`
3. Проверка обязательных полей — все присутствуют и не пустые, иначе `400`
4. Проверка формата полей — символы, длина, паттерн, иначе `400`
5. Проверка сложности пароля — uppercase, lowercase, цифра, спецсимвол, ≥8 символов, иначе `400`
6. Верификация reCAPTCHA — запрос к Google API, иначе `400`
7. Проверка уникальности username — `SELECT` в БД, если занят `409`
8. Хэширование пароля — bcrypt/Argon2, открытый пароль не хранится
9. Формирование записи — генерация UUID, `createdAt = NOW()`
10. `INSERT` в БД — при ошибке `500`
11. Возврат `201` с `userId`, `username`, `message`
